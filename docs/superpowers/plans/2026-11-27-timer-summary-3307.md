# Timer Summary and Separate Edit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Resolve GitHub issue #3307 by replacing disabled timer forms with readable summaries and a separate edit/actions flow, then refresh smoke automation and Guide 2 artifacts.

**Architecture:** Reuse `ControllerSummary` and the `Collapsible` separate-edit contract already shipped for dosing pumps. Extract the cron description rules into a focused utility shared by doser and timer summaries, while keeping timer persistence and Formik field names unchanged. Playwright will open the accessible actions menu instead of targeting legacy icon IDs, and Guide 2 will save the example before capturing the resulting summary row.

**Tech Stack:** React, Formik, Jest, Playwright, reef-pi design-system primitives.

**Spec:** <https://github.com/reef-pi/reef-pi/issues/3307>

## Global Constraints

- Preserve every timer field, existing smoke test ID, and the schedule editing behavior fixed in #3259.
- Use `var(--reefpi-*)` for any new styling; add no raw hex values.
- Keep every interactive target at least 44px through existing design-system primitives.
- One issue per PR; commit and PR title use the `[Codex design]` prefix.
- Do not introduce a feature flag; issue #3307 does not request one.

## Review Focus

- Boolean values may arrive as booleans or strings; action and revert wording must remain correct for both.
- Deleted or unavailable targets must render a stable fallback instead of crashing the list.
- Reminder timers have subject/message but no on/off or duration semantics.
- Non-daily or stepped cron expressions must show every field rather than looking like a single clock time.
- Edit cancellation must return to the read-only summary without submitting or removing smoke selectors from the edit form.
