# Macro Summary and Separate Edit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Resolve GitHub issue #3308 with a readable ordered macro summary and a separate accessible edit/actions flow while preserving macro execution and persistence.

**Architecture:** Add a pure `MacroSummary` presentation component that resolves stored step configuration against the target collections already loaded in Redux and renders numbered values through `ControllerSummary`. Wire it beside the existing `MacroForm` under the established `Collapsible` separate-edit contract; keep Run/Revert buttons and persistence handlers unchanged. Update Playwright helpers to consume the accessible actions menu.

**Tech Stack:** React, Redux, Formik, Jest, Playwright, reef-pi design-system primitives.

**Spec:** `docs/superpowers/specs/2026-11-27-macro-summary-3308-design.md`

## Global Constraints

- Preserve macro API payloads, step ordering, #3241 persistence behavior, Run/Revert behavior, and every existing smoke test ID.
- Use existing `var(--reefpi-*)` tokens; introduce no raw hex literals, fonts, dependencies, or feature flag.
- Keep interactive targets at least 44px through existing design-system primitives.
- One issue per PR; commit and PR title use the `[Codex design]` prefix.

## Review Focus

- Boolean `on`, `enable`, and `reversible` values may be booleans or strings; summary wording must normalize both forms.
- A deleted or unavailable target must show its stored ID, while a missing ID must show `Not configured` rather than crash.
- Empty and malformed step/config arrays must render a stable read-only fallback.
- Repeated step types must retain API order and unique numbered labels.
- Nested macro and subsystem steps need domain wording (Run/Reverse and Enabled/Disabled) rather than equipment-only wording.
